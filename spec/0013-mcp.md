# Spec 0013 — MCP Server

## Context

cabin already exposes its capabilities over a REST API (spec 0008). This spec
adds a Model Context Protocol server so an assistant (Claude Code and friends)
can operate the CA directly: look up the CA, list and inspect certificates,
issue one, sign a CSR, and revoke. The MCP server is a second consumer of the
same domain services — no new certificate logic.

## User Stories

- As an operator using Claude Code, I point my client at
  `https://ca.example.org/mcp`, authenticate with a cabin API token, and ask
  for a certificate for a new host without leaving the terminal.
- As an operator, MCP is off until I enable it, and every MCP action lands in
  the audit log with the token that performed it.

## Functional Requirements

- FR-1: Dependency `fastmcp` (PrefectHQ, Apache-2.0). The MCP app is mounted
  as an ASGI sub-app at `/mcp` via `mcp.http_app()` + Starlette `Mount`.
  Mind the known sub-path issue (python-sdk#1367): assert in a test that the
  advertised endpoint path is correct under the `/mcp` prefix.
- FR-2: Authentication reuses spec-0008 API tokens: the `Authorization:
Bearer <secret>` header is verified with `api_tokens.verify_token`; the
  token's role gates the tools exactly like the REST API (viewer = read-only).
  No session cookies, no CSRF. Missing/invalid token → the MCP transport's
  401; a role failure → a tool error with a clear message (not a crash).
- FR-3: Tools (names are the contract; keep them stable):
  - `get_ca_info()` — subjects, fingerprints, validity, base URL, ACME
    directory URL when enabled (viewer+)
  - `list_certificates(query=None, status=None, page=1)` — the spec-0006
    inventory, same filters, returns metadata only (viewer+)
  - `get_certificate(certificate_id)` — metadata + PEM chain; the private key
    is NEVER returned by any MCP tool, regardless of role (viewer+)
  - `issue_certificate(subject_cn, sans=[], profile="server",
key_type="ecdsa-p256", days=365)` — issues and returns metadata +
    cert_pem + **key_pem** (admin+; this is the one tool that returns a key,
    because the caller cannot obtain it any other way)
  - `sign_csr(csr_pem, profile="server", days=365, sans=None)` — admin+
  - `revoke_certificate(certificate_id, reason="unspecified")` — admin+
    Every tool has a docstring that the model sees; parameter validation mirrors
    the REST models (days 1..3650, ≤100 SANs, CN ≤64) and errors come back as
    readable messages, never tracebacks.
- FR-4: Enablement: setting `mcp_enabled` (default false) on the settings
  page. When off, `/mcp` returns 404. Requires `base_url` for the same reason
  ACME does (published URLs).
- FR-5: Audit: every mutating tool records the existing actions
  (cert_issued/cert_signed/cert_revoked) with `actor_kind="token"` and the
  token label, plus the detail `{"via": "mcp"}` so MCP-driven changes are
  distinguishable. The `source` column (spec 0012) gets a new value `mcp`.
- FR-6: A `/mcp` info section on the settings or ACME page: the endpoint URL,
  a note that an API token is required, and a ready-to-paste
  `claude mcp add --transport http cabin <url> --header "Authorization: Bearer <token>"`
  snippet.

## Acceptance Criteria

- AC-1: With `mcp_enabled=false`, `/mcp` and any sub-path return 404.
- AC-2: With it on, an MCP client (the `fastmcp` in-process client, or a raw
  JSON-RPC POST if that is simpler) lists exactly the six tools with their
  schemas.
- AC-3: No token → 401; viewer token → read tools work, `issue_certificate`,
  `sign_csr` and `revoke_certificate` are refused with a role message; admin
  token → all six work.
- AC-4: `issue_certificate` produces a real certificate that chains to the
  intermediate, appears in `/certs` with source `mcp`, and returns a key that
  matches it; `get_certificate` on the same id returns no key material for
  any role.
- AC-5: `sign_csr` with the smuggling CSR from spec 0005 yields a leaf without
  CA extensions; a malformed CSR returns a readable error.
- AC-6: `revoke_certificate` marks it revoked and the serial appears in
  `/crl`; revoking twice is not an error (idempotent, like the API).
- AC-7: Every mutating tool call writes exactly one audit event with
  `actor_kind="token"` and `via: mcp`; read tools write none.
- AC-8: Parameter validation rejects days=0/4000, 101 SANs and a 65-char CN
  with readable messages.

## Out of Scope

MCP resources and prompts (tools only), streaming/SSE specifics beyond what
the transport gives, OAuth or any auth other than cabin API tokens, tools for
user/token/CA management (issuance and revocation only), rate limiting.
