{# Spec 0029 FR-3: one macro per previewed page, called from the page template as `{{ macro(preview) }}` and from the preview handler through the environment's own module access (`web/deps.py:preview_fragment`). Both envelopes therefore render the *same* markup -- AC-7 asserts the fragment appears verbatim inside the page -- which is what makes "one code path" a fact rather than a resemblance. Each macro takes exactly one argument, the preview dictionary its handler built, and reads nothing from the surrounding template context: that is what lets `.module` render it at all, and it is why nothing here is imported `with context`. `preview` is None on a first GET, before anything has been typed. Every macro folds that into an empty mapping first, so the panel shows the design's dashes rather than a blank column, and what it shows stays a pure function of its one argument rather than of a second code path. `data-dim` is the unparsed state of a value (FR-10): --text-muted rather than the design's #5a5d6b, which is 2.4:1 on --surface and would be reported by the contrast probe. An attribute and not a class, because FR-15 closes the set of classes this spec defines at seven and a rule for an eighth would have no argument beside it. This is a macro library and not a page: it extends nothing, defines no `content` block and sets no `nav_current`, which is why `test_every_content_template_sets_nav_current` exempts it -- and asserts exactly those absences, so the exemption cannot be widened to silence a real page. #} {% macro issue_panel(preview) %}{% set p = preview or {} %}
